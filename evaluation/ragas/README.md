# Tabular RAG RAGAS Evaluation

This is the offline evaluation suite for the production Tabular RAG chatbot. It is separate from `evaluation/langsmith/`: LangSmith continues to assess multi-agent/dashboard workflow behaviour, while this suite assesses chat evidence retrieval, reranking and grounded final answers.

The executable invokes the real production path directly: `build_chat_graph()` → guardrail → BGE-small session-scoped Supabase vector retrieval (top 8) → `BAAI/bge-reranker-v2-m3` (top 4) → one production chat-model call → deterministic grounding. It never calls the HTTP API and does not alter production chat behaviour.

RAGAS judge calls are offline evaluation calls. They are not part of the chatbot's one-LLM-call production runtime.

## Prerequisites and setup

Set `BI_PIPELINE_MODE`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, and `GROQ_API_KEY`. The judge model defaults to the configured production chat Groq model (`openai/gpt-oss-20b` at present); override it with `RAGAS_EVALUATOR_MODEL`. The judge uses temperature zero.

Use a dedicated evaluation workspace/session, never a user workspace. Create it through the normal application flow with exactly one uploaded dataset, then either run the normal analysis/indexing pipeline or refresh only that dedicated session from the checked-in corpus. The runner reads that workspace's real dataset ID before indexing; a session UUID is not itself a valid dataset ID:

```powershell
python -m evaluation.ragas.runner --session-id <dedicated-evaluation-session-id> --index-evaluation-data
```

`--index-evaluation-data` calls the production `Retriever.index_dataset()` and replaces only the supplied session's Supabase document chunks. It uses `evaluation/data/sme_gym_sales_2015_2025-1.csv`; deleting the dedicated workspace through the application’s normal workspace lifecycle removes its associated data. The runner first queries `document_chunks` read-only and reports every indexed document type. It warns clearly when types declared by answerable cases are absent.

To run an already indexed session, including repetitions:

```powershell
python -m evaluation.ragas.runner --session-id <dedicated-evaluation-session-id> --repetitions 3
```

For a retrieval-only dry run that makes no offline judge calls, add `--skip-ragas`.

## Cases and metrics

`cases.json` contains 19 manually authored, readable cases for the checked-in gym-sales corpus. Every answerable case has a human reference answer and logical `reference_source_ids`; these are not generated by the chatbot. The deterministic baseline index uses source IDs produced by the production document builder, such as `numeric_net_revenue_gbp` and `category_branch_net_revenue_gbp`.

Non-answerable cases deliberately have no reference source IDs. They are excluded from Context Precision, Context Recall and deterministic relevance metrics, and separately report whether grounding abstained, hallucinated numerical claims, or returned unsupported source IDs.

The four RAGAS collections metrics are Context Precision, Context Recall, Faithfulness and Factual Correctness (the collection metric's default F1 behaviour). The runner uses the current `ragas.metrics.collections` API and `ragas.llms.llm_factory`. RAGAS 0.4.3 has a Groq-adapter defect, so its OpenAI-compatible client is pointed at Groq's official API endpoint; the evaluator still uses only `GROQ_API_KEY` and Groq models.

Deterministic, source-level binary metrics are Precision@K, Recall@K, Hit@K, MRR and NDCG@K. They are computed before reranking (configured top 8) and after reranking (configured top 4), de-duplicating chunks that map to the same logical source. `reranker_comparison.csv` additionally compares both systems at K=4, so ordering improvements are not obscured by different list sizes.

## Outputs

The default `evaluation/ragas/results/` directory contains:

- `ragas_case_results.csv` — readable case/run rows, IDs, types, scores, outcome and latency.
- `ragas_case_results.jsonl` — full raw and reranked evidence records (including scores/content).
- `ragas_summary.csv` — report-ready mean/median/min/max metrics and applicability counts.
- `reranker_comparison.csv` — before/after Precision@4, MRR and NDCG@4.

Execution errors are retained in every output; failed and unsupported cases are never silently dropped.
